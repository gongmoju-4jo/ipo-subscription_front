# 유비쿼터스 언어 (프론트 발췌)

원본은 백엔드(`ipo-subscription`)의 `docs/UBIQUITOUS_LANGUAGE.md`다. **원본이 기준이고, 이 문서는 화면과 타입에 필요한 부분만 옮긴 것**이다. 원본이 바뀌면 이 문서도 맞춘다.

## 규칙

- 타입, 변수, 상태값 이름은 아래 코드명을 그대로 쓴다 (API 응답 필드와 같은 이름)
- 화면 문구도 "한글" 열의 단어를 쓰고, "쓰지 않을 말"은 화면에도 쓰지 않는다
- 표에 없는 이름이 필요하면 임의로 만들지 말고 먼저 묻는다
- 문서에 없는 상태값, 필드, API 형식은 임의로 정하지 않는다

## 1. 핵심 개념

| 한글 | 코드명 | 뜻 | 쓰지 않을 말 |
| --- | --- | --- | --- |
| 공모주 (종목) | `Ipo` | 상장하면서 일반에 새로 파는 주식 | 상품, 주식 |
| 공모가 | `offerPrice` | 수요예측으로 확정된 1주 가격 | 가격, 단가 |
| 일반청약 물량 | `retailQuantity` | 일반투자자에게 배정할 총 주식 수 | 재고, 수량 |
| 청약 | `Subscription` | 투자자가 공모주를 사겠다고 신청한 1건 | 주문, 신청 |
| 청약 수량 | `requestedQuantity` | 투자자가 신청한 주식 수 | 주문 수량 |
| 청약 금액 | `subscriptionAmount` | 청약 수량 x 공모가 | 주문 금액 |
| 예수금 | `cashBalance` | 자유롭게 쓸 수 있는 돈 (출금 가능액) | 잔액, 현금 |
| 청약증거금 | `marginBalance` | 청약에 잡혀 있는 증거금의 합계 | 묶인 금액 |
| 증거금 | `Margin` | 청약 금액 x 증거금률. 청약 1건당 1개 | 보증금, 예치금 |
| 증거금률 | `marginRate` | 우리 프로젝트는 100% | - |
| 최소 청약 수량 | `minQuantity` | 종목별 최소 신청 수량 | - |
| 청약 한도 | `maxQuantity` | 1인당 최대 신청 수량 | - |
| 청약 기간 | `subscriptionStartAt`, `subscriptionEndAt` | 청약 받는 시작/마감 시각 | 판매 기간 |
| 마감 | `close` | 청약 기간 종료. 이후 신청, 취소 불가 | 종료 |
| 청약 취소 | `cancel` | 마감 전 투자자가 청약을 철회 (SHOULD) | 환불 |
| 계좌 | `Account` | 투자자 명의의 증권 계좌 (가상). 1인 여러 개 가능 | 통장 |
| 계좌번호 | `accountNumber` | 화면에 보여주는 숫자 12자리. 다른 API는 `accountId`로 참조 | 계좌 ID와 혼용 |
| 원장 | `LedgerEntry` | 돈이 움직일 때마다 남기는 기록 (추가만) | 로그, 이력 |

> 화면에는 `accountNumber`를 보여 주고, API 호출에는 `accountId`를 쓴다. 둘을 섞지 않는다.

## 2. 증거금 상태 (돈의 움직임)

| 한글 | 코드명 | 뜻 | 쓰지 않을 말 |
| --- | --- | --- | --- |
| 증거금 인출 | `PENDING` | 예수금에서 청약증거금으로 옮김 | 묶기, 홀드, 차감, 확보 |
| 정산 | `POSTED` | 배정 대금만큼 청약증거금에서 실제로 차감, 나머지는 예수금으로 환불 | 결제 |
| 증거금 반환 | `VOIDED` | 청약증거금 전액을 예수금으로 되돌림 (확정 실패, 취소, 0주 배정) | 풀기, 환불, 취소, 해제 |

## 3. 배정, 환불

| 한글 | 코드명 | 뜻 | 쓰지 않을 말 |
| --- | --- | --- | --- |
| 배정 | `Allocation` | 마감 후 청약자에게 주식을 나눠주는 것 | 당첨, 지급 |
| 균등배정 | `EQUAL` | 최소 수량 이상 신청자에게 똑같이 나눔 | - |
| 비례배정 | `PROPORTIONAL` | 신청 수량에 비례해서 나눔 | - |
| 경쟁률 | `competitionRate` | 신청 수량 / 배정 물량 | - |
| 배정 수량 | `allocatedQuantity` | 청약 1건에 배정된 주식 수 (0주 가능) | 당첨 수량 |

| 환불 | `Refund` | 정산 후 남은 증거금(증거금 - 배정 대금)을 예수금으로 돌려줌 | 취소, 반환 |
| 청약 미달 | `undersubscribed` | 신청 수량이 물량보다 적음 | - |

## 4. 청약 상태값

화면 칩 문구는 `src/lib/domain.ts`의 매핑을 따른다.

| 상태 | 코드명 | 뜻 |
| --- | --- | --- |
| 접수됨 | `PENDING` | API가 받았고 처리 중 (202 응답 시점) |
| 확정 | `CONFIRMED` | 증거금 인출 완료, 청약 유효 |
| 거절 | `REJECTED` | 잔액 부족, 이중청약 등으로 인출 전에 실패. 재청약 가능 |
| 보상 중 | `COMPENSATING` | 인출됐는데 확정에 실패해 증거금 반환을 요청한 상태 |
| 취소 요청 | `CANCEL_REQUESTED` | 투자자가 취소 요청, 처리 중 (SHOULD) |
| 취소됨 | `CANCELLED` | 취소 또는 확정 실패 보상 완료. 재청약 가능 |
| 배정 완료 | `ALLOCATED` | 마감 후 배정 수량 확정 |
| 환불 완료 | `REFUNDED` | 정산과 환불까지 끝남 (0주면 증거금 전액 반환) |

- 처리 중(진행 중)으로 보는 상태: `PENDING`, `COMPENSATING`, `CANCEL_REQUESTED`. 이 동안은 상태가 바뀔 수 있어 화면이 다시 조회해야 한다

## 7. 헷갈리기 쉬운 것 (화면 문구에 특히 주의)

- **반환 vs 환불**: 반환(`VOIDED`)은 청약이 유효하지 않게 돼 증거금 전액을 되돌리는 것 (확정 실패, 취소, 0주 배정). 환불은 배정 후 정산하고 남은 금액을 돌려주는 것
- **인출 vs 정산**: 인출(`PENDING`)은 예수금 → 청약증거금 이동 (아직 내 돈, 쓸 수만 없음). 정산(`POSTED`)은 배정 대금만큼 실제로 빠짐
- **예수금 vs 청약증거금**: 둘 다 같은 계좌 안의 돈. 예수금은 쓸 수 있고, 청약증거금은 청약에 잡혀 있음
- **청약 상태 `PENDING` vs 증거금 상태 `PENDING`**: 청약 `PENDING`은 "접수됐고 처리 중", 증거금 `PENDING`은 "인출돼서 정산이나 반환을 기다리는 중". 다른 테이블의 상태값이라 한 타입으로 합치지 않는다
- **거절 vs 보상**: 거절(`REJECTED`)은 돈을 옮기기 전에 실패해 되돌릴 것이 없다. 보상(`COMPENSATING` → `CANCELLED`)은 돈을 옮긴 뒤 실패해 반환이 필요하다
- **일반청약 물량 vs 배정 수량**: 물량은 종목 전체 몫, 배정 수량은 청약 1건이 받은 수
- **공모주 `ALLOCATED` vs 청약 `ALLOCATED`**: 같은 이름이지만 공모주는 "종목의 배정이 끝남", 청약은 "이 청약의 배정 수량이 정해짐". 타입을 따로 둔다
- **청약 vs 주문**: 일반 주식 매매와 다르다. 신청한 만큼 못 받고 나눠 받는다

## 범위 밖

이중청약 판정 상태(`ELIGIBLE`, `PROVISIONAL_INELIGIBLE`, `PENDING_JUDGEMENT`, `INELIGIBLE`), 중앙기관(`Clearing`), 통합 경쟁률은 백엔드에서 COULD(MVP 밖)라 옮기지 않았다. `ALREADY_SUBSCRIBED`(거절 사유)는 같은 증권사에서 같은 종목을 다른 계좌로 또 청약했을 때 나오는 코드다.
